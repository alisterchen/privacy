# 專案規則

> 放在每個專案 repo 的根目錄。先填「專案資訊」，再依專案類型保留需要的「加強標準」，刪掉用不到的段落。

## 專案資訊

- 專案名稱：
- 目標平台：
- 主要語言與框架：
- 負責人：專案負責人（只有負責人能合併 PR、上架、上線）

## 工作規則

1. 開工前先讀 `STATUS.md`，從「下次從哪裡開始」接手。
2. 變更走分支和 PR，不直接推到 main。
3. 不得為了讓測試或 CI 通過而停用、跳過或刪除測試。
4. 密碼、API key、金鑰放在環境變數或設定檔，並確認該檔已列入 `.gitignore`。
5. 遇到以下情況先停下來問負責人，不要自己決定：
   - 需求不清楚或範圍要變動
   - 要改架構、換技術、刪功能
   - 要合併 PR、上架、上線、動到正式環境或產線設備
6. **每次工作階段結束前，一定要更新 `STATUS.md`**，照範本每一節填寫實際狀況。

## 完成標準（所有專案）

- [ ] 需求清單中的每一項都有對應實作
- [ ] 單元測試全部通過，CI 綠燈
- [ ] 沒有寫死的密碼、API key、金鑰
- [ ] README 寫清楚安裝方式和執行方式
- [ ] `STATUS.md` 已更新

## 加強標準：手機 App（Android / iOS）

- [ ] 在實機上安裝並跑過主要流程（寫明裝置型號和系統版本）
- [ ] 版本號和 build 號已遞增
- [ ] 上架說明、截圖、隱私權說明已準備好（送審由負責人操作）

## 加強標準：跨平台（Windows / macOS / 多平台共用）

- [ ] 每個目標平台都實際建置並執行過
- [ ] 畫面遵守共用設計系統（顏色、字級、按鈕元件）
- [ ] 安裝包或執行檔可以在乾淨的電腦上安裝

## 加強標準：網站、爬蟲、排程服務

- [ ] 排程時間和時區寫在 README（含夏令時間的處理方式）
- [ ] 抓取失敗或資料異常時會通知
- [ ] 最近一次正式執行的結果記在 `STATUS.md`（時間、筆數）

## 加強標準：生產線自動化

- [ ] 異常處理：設備斷線、感測器數值異常、通訊逾時都有處理
- [ ] 安全：急停和安全連鎖不經過本程式，或已經過負責人確認
- [ ] 回滾方案：寫清楚出問題時如何回到上一版
- [ ] 操作手冊（runbook）：現場人員看得懂的啟動、停止、排除故障步驟
- [ ] 先在測試環境或模擬器驗證過，才上正式產線
